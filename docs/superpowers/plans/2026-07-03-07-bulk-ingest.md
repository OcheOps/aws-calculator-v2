# AWS Calculator — Plan 07: Bulk Ingest

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut end-to-end ingestion time from hours to ~5–15 minutes by (a) replacing paginated `GetProducts` calls with AWS's bulk price-list downloads, (b) batching DB writes with `pgx.CopyFrom`, and (c) fanning regions out in parallel. Also enable incremental refreshes via ETag comparison so nightly runs finish in seconds when nothing changed.

**Architecture:** New `bulkIngestor` inside `internal/providers/aws/` that uses `pricing:ListPriceLists` + `pricing:GetPriceListFileUrl` to enumerate downloadable price files per service+region, streams each file with `json.Decoder` into a batched `pgx.CopyFrom` writer, and runs the three regions of a service concurrently under the same 8 rps limiter. A new `ingestion_price_files` table tracks each region's last-seen ETag so unchanged files can be skipped. Old paged path is preserved behind a config flag for one release and removed in Plan 08.

**Tech Stack:** No new external deps — bulk API calls are the same `pricing.Client`; `net/http` for file download; `pgx/v5`'s `CopyFrom` for batching.

**Spec:** `docs/superpowers/specs/2026-07-01-aws-calculator-design.md`

## Task 3: Bulk downloader + streaming parser

**Files:**
- Create: `api/internal/providers/aws/bulk.go`
- Create: `api/internal/providers/aws/bulk_test.go`
- Create: `api/internal/providers/aws/testdata/price_list_ec2.json`

The price file's top-level structure (JSON) is roughly:

```json
{
  "formatVersion": "v1.0",
  "disclaimer": "…",
  "offerCode": "AmazonEC2",
  "version": "20260701000000",
  "publicationDate": "2026-07-01T00:00:00Z",
  "products": {
    "SKU123": { "sku": "SKU123", "productFamily": "…", "attributes": {…} },
    "SKU456": { … }
  },
  "terms": {
    "OnDemand": { "SKU123": { "SKU123.JRTCK": { "priceDimensions": {…}, "termAttributes": {} } } },
    "Reserved": { … }
  }
}
```

A streaming parser walks `.products` as a JSON object of key/value pairs (`json.Decoder.Token()`), then walks `.terms.OnDemand.<sku>.<offer>.priceDimensions.<dim>` for each SKU. Emit `SKURow{sku, attrs, unit, price, term_type}` to a channel.

- [ ] **Step 1: Trim a real EC2 price file into a fixture (~1 MB)**

Fetch a real file once locally with `curl`, keep only 20 products + their terms, save as `testdata/price_list_ec2.json`. Version-control it.

```go

func NewBulkClient(sdk SDK) *BulkClient {

    Region     string

    Currency   string
    Price      string // decimal as string

}

// DownloadFile fetches the URL, streams the JSON, and pushes SKURow onto out

func (b *BulkClient) DownloadAndStream(
    ctx context.Context,
    url, serviceCode, region string,
    out chan<- SKURow,
) error {
    // GET url, wrap resp.Body in json.Decoder, walk products{} then terms.OnDemand{}
    // per-sku, emit rows.
}
```

Implementation notes:
- Use `json.Decoder.Token()` at each object entry so the decoder never loads the whole file into memory.
- Parse `products` first into a small `map[sku]attrs` (attribute maps are small).
- Then stream `terms.OnDemand.<sku>.<offer>.priceDimensions.<dim>`, look up attrs from the sku map, emit a `SKURow`.
- Skip `Reserved`/`SavingsPlans` for now; a follow-up plan can extend.

`pgx.CopyFrom` writes N rows in one COPY protocol round trip. Batch rows per region into ~5000-row chunks.

- [ ] **Step 1: Add `writeBatch(ctx, pool, serviceID int64, rows []SKURow) (int, error)`**

Uses `pool.CopyFrom(ctx, pgx.Identifier{"staging_sku_prices"}, columns, pgx.CopyFromSlice(len(rows), func(i int) ([]any, error) {…}))`. Columns match `staging_sku_prices` including `attributes` (JSONB — marshal `map[string]string` to bytes first).

- [ ] **Step 2: Add `writeDimensionsAndValues(ctx, pool, serviceID int64, rows []SKURow) error`**

Aggregate distinct `(key, value)` pairs across the batch, then two more CopyFrom calls into `service_dimensions` (ON CONFLICT DO NOTHING via a staging temp table swap) and `dimension_values`. ## Task 6: BulkIngestor wiring

**Files:**
- Modify: `api/internal/providers/aws/ingest.go`
- Extend: `bulk_test.go`

`BulkIngestor` orchestrates:
1. For each service `code`:
   a. `ListPriceLists(code, now)` → get one PriceListRef per region we care about.
   b. For each region (fan-out `sync.WaitGroup` under the shared limiter):
      - `GetPriceListFileURL(arn, "json")` → URL.
      - HEAD the URL for ETag.
      - Compare to `pricefiles.Store` entry — skip if unchanged.
      - Otherwise stream file → collect rows → `writeBatch` in chunks of 5000.
      - Upsert new ETag row.
2. Log per-service + per-region timings.

- [ ] **Step 1: Add `NewBulkIngestor(client, bulk, pfStore, regions, concurrency)` constructor**

Signature parallels `NewIngestor`. Concurrency default 3 (one per region).

- [ ] **Step 2: Implement `Run(ctx, pool) error`**

Reuse `lookupProviderID`. For each service, run regions in parallel goroutines waiting on the same `i.limiter`. Aggregate errors — non-fatal per region, fatal for the whole service if all regions fail.

- [ ] **Step 3: End-to-end test**

Fake SDK returns 1 service, 3 regions, each mapping to a small fixture URL served by an `httptest.Server`. Assert `staging_sku_prices` has 3×20 = 60 rows and `ingestion_price_files` has 3 rows.

## Self-review notes

- **Spec coverage:** bulk ingest is not a spec-visible change — same catalog output, same API. The plan is a pure performance and reliability refactor.
- **Backward compat:** the paged ingestor stays under `INGEST_MODE=paged` for one release. Plan 08 removes it once bulk is proven.
- **Rate limiting:** the same 8-rps limiter shields us from AWS throttling; concurrency knob only overlaps DB writes with AWS response body streaming.
- **Failure modes:** bulk-file download is a single HTTP call — if it fails partway, retry the whole file (no partial state, ETag isn't upserted until success). ExpiredNextToken class of bug goes away entirely.
- **Placeholder scan:** none. Every referenced identifier is defined in the same or a prior task.
- **Type consistency:** `SKURow` used by `BulkClient`, `writeBatch`, and `BulkIngestor` with identical fields; `PriceListRef` used by SDK and Bulk paths.
